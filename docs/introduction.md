# 喵乐个鱼（miaolegeyu）产品介绍

## 一、产品定位

**喵乐个鱼**是一款基于微信生态的**社交餐饮决策平台**，专注于解决"今天吃什么"这一永恒难题。不同于传统的外卖或点评应用，喵乐个鱼将"选餐厅"从个人决策转变为**群体协作游戏**——通过投票、拼单、时间协调、约饭等多种互动模式，让聚餐决策变得轻松有趣。

产品名称"喵乐个鱼"融合了猫咪的治愈感与鱼塘的社交隐喻，传递出轻松、温暖、有归属感的品牌调性。在视觉设计上，采用**蜡笔像素风**配合暖色调主色（橘色 #FF9F43），营造出手绘童趣与数字像素碰撞的独特美学，让用户在每一次打开小程序时都能感受到温暖与愉悦。

## 二、目标用户

### 核心用户画像

| 用户类型 | 年龄段 | 典型场景 | 痛点 |
|---------|--------|----------|------|
| **职场白领** | 22-35岁 | 团队午餐、部门团建 | 众口难调、决策耗时过长 |
| **大学生** | 18-25岁 | 室友聚餐、社团活动 | 预算有限、选择困难症 |
| **年轻家庭** | 25-35岁 | 家庭聚会、亲子用餐 | 需要兼顾老幼口味偏好 |
| **美食爱好者** | 20-40岁 | 探店打卡、朋友小聚 | 想发现新店但缺乏可靠推荐源 |

### 用户特征洞察

- **重度微信用户**：日常沟通高度依赖微信群，习惯通过分享链接进行社交协作
- **决策疲劳者**：面对海量餐饮信息时容易陷入选择困境
- **社交活跃型**：重视线下聚会体验，愿意为优质社交关系投入时间
- **审美敏感度**：对产品的视觉设计和交互体验有较高要求

## 三、核心价值主张

### 1. 决策民主化 —— "不再一个人扛"

传统模式下，组织聚餐的人往往承担着巨大的决策压力。喵乐个鱼通过**四种决策模式**，让每个人都能参与其中：

- **我选好了（Mode A）**：发起人提前做好功课，提供精选候选，好友只需投票
- **你们来定（Mode B）**：发起人设定条件框架，由参与者共同提议和筛选
- **拼单模式（Group）**：外卖/堂食多人各自选择，系统自动汇总统计
- **约饭模式（Pick for Them）**：基于店铺发起即时邀约，带倒计时营造紧迫感

### 2. 时间协同化 —— "找到大家都空的时间"

内置**时间投票模块**，支持多时段多选项投票，自动统计每个人的空闲时间窗口，用数据说话，告别反复确认"你周六下午有空吗？"的低效沟通。

### 3. 发现社区化 —— "朋友推荐的才靠谱"

**新店探索功能**让每位用户都能成为美食发现者。上传店铺、撰写评价、标记兴趣，构建起基于真实社交关系的美食推荐网络，比算法推荐更具信任感。

### 4. 体验游戏化 —— "吃饭也可以很好玩"

- **游动小鱼动画**：首页的动态元素带来视觉愉悦
- **鱼塘概念**：活动大厅被包装成"鱼塘"，所有进行中的活动如同池中的鱼儿
- **匿名模式**：保护害羞用户的参与意愿
- **密码房间**：为私密聚会增添仪式感

## 四、设计理念

### 视觉语言：蜡笔 × 像素

喵乐个鱼的视觉体系建立在两个看似矛盾的元素的融合之上：

- **蜡笔质感**：手绘的不完美感传递温度与人情味，对抗数字产品的冷峻感
- **像素风格**：致敬经典游戏的怀旧情怀，降低使用门槛，让操作像玩游戏一样直观

这种独特的美学定位不仅体现在UI界面上，更贯穿于交互动效、图标设计、空状态提示等每一个细节。

### 交互原则

1. **极简路径**：从发起活动到邀请好友，不超过3次点击
2. **即时反馈**：每次操作都有明确的视觉或动效反馈
3. **容错设计**：允许修改已发布的信息，支持退出/取消操作
4. **渐进式披露**：复杂功能分层展示，新用户不会被高级功能淹没

### 信息架构

采用**自定义TabBar**的三栏结构：
- **首页**：品牌展示 + 功能入口 + 活动发现
- **喵不喵（鱼塘）**：所有进行中活动的聚合中心
- **我的**：个人中心 + 设置 + 历史记录

子包按业务域划分（package-create / package-vote / package-shop / package-schedule / package-user / package-admin），确保代码可维护性与团队协作效率。

## 五、技术亮点

### 微信云开发全栈方案

喵乐个鱼采用**微信云原生开发**模式，技术栈包括：

- **前端**：WXML + WXSS + JavaScript（微信原生框架）
- **后端**：云函数（Serverless架构，按量计费）
- **数据库**：云数据库（NoSQL文档数据库）
- **存储**：云存储（图片、海报等媒体文件）

这种架构的优势在于：

| 维度 | 传统方案 | 云开发方案 |
|------|----------|------------|
| 部署成本 | 需要服务器+域名+备案 | 零运维，开箱即用 |
| 开发效率 | 前后端分离，联调复杂 | 统一项目，调用简洁 |
| 扩展性 | 需手动扩容 | 自动弹性伸缩 |
| 安全性 | 自行实现鉴权 | 微信原生身份体系 |

### 核心技术特性

1. **50+ 云函数覆盖全业务链路**
   - 从用户登录到内容审核，从实时投票到定时任务，每个业务环节都有独立的云函数支撑
   - 函数粒度细，职责单一，便于维护和测试

2. **18 个数据库集合的精细化建模**
   - rooms / room_participants / votes（投票核心）
   - group_order_participants（拼单）
   - schedule_votes / schedule_vote_participants（时间投票）
   - dining_appointments / dining_appointment_participants（约饭）
   - shops / users / reports / feedbacks（内容与用户）
   - admin_logs / config / message_subscriptions / events（系统级）

3. **三级隐私控制机制**
   - `friends`（仅好友可见）：适合私密聚会
   - `public`（公开）：适合开放性活动
   - `share`（仅链接访问）：平衡隐私与传播

4. **双重内容安全检测**
   - 服务端敏感词过滤（即时拦截）
   - 微信内容安全API调用（合规保障）

5. **自动化运维能力**
   - 定时触发器自动锁定过期房间
   - 7天过期数据自动清理规则
   - 操作日志审计追踪

6. **AI 能力集成**
   - 店铺识别（recognizeShop）：拍照即可创建店铺信息
   - 附近餐厅搜索（searchNearbyRestaurants）：基于地理位置的智能推荐

## 六、使用场景描述

### 场景一：周五团队午餐决策

> **人物**：小李（产品经理），需要组织5人的团队午餐
>
> **痛点**：大家口味不同，有人想吃辣，有人要清淡，群里讨论了半小时还没结果
>
> **解决方案**：
> 1. 小李打开喵乐个鱼 → 发起"我选好了"投票
> 2. 提前挑选3家候选餐厅（川菜、粤菜、轻食），附上菜单截图
> 3. 生成分享链接发到微信群
> 4. 同事们点开链接，每人投一票
> 5. 10分钟后查看结果，得票最高的餐厅胜出
>
> **价值**：决策时间从30分钟缩短至10分钟，且无人觉得被忽视

### 场景二：跨部门团建时间协调

> **人物**：小王（HR专员），需要安排20人的季度团建
>
> **痛点**：大家日程各异，微信群接龙混乱，反复调整时间
>
> **解决方案**：
> 1. 小王创建时间投票，列出本周五/六/日的上午、下午、晚上共9个时段
> 2. 分享给所有参与者
> 3. 每人勾选自己有空的时间段
> 4. 系统自动统计，显示"周六下午14:00-18:00 有18人可选"
> 5. 确定时间后，再发起餐厅投票
>
> **价值**：一次收集所有人的时间偏好，避免反复沟通

### 场景三：办公室下午茶拼单

> **人物**：小张（运营），想点奶茶但不想单独付配送费
>
> **痛点**：群里喊一声响应寥寥，凑不够起送门槛
>
> **解决方案**：
> 1. 小张发起拼单活动，选择附近的奶茶店
> 2. 设定截止时间为30分钟后
> 3. 同事们加入拼单，各自选择想要的饮品
> 4. 截止后系统汇总订单，生成结算清单
>
> **价值**：透明化的拼单流程，避免算错账的尴尬

### 场景四：发现隐藏美食宝藏

> **人物**：小陈（美食博主粉丝），喜欢探索新店
>
> **痛点**：大众点评上的信息同质化严重，缺乏个性化推荐
>
> **解决方案**：
> 1. 在新店探索页面浏览其他用户上传的店铺
> 2. 发现一家评分高的小众日料店
> 3. 点击"我想被约"，标记对该店的兴趣
> 4. 或直接发起约饭活动，邀请朋友一起去探店
>
> **价值**：基于真实社交关系的推荐，比算法更值得信赖

### 场景五：异地好友云端聚餐

> **人物**：小刘（北漂），想和老家的朋友们"一起吃饭"
>
> **痛点**：无法物理相聚，但想保持联系
>
> **解决方案**：
> 1. 创建一个公开的投票房间
> 2. 各自在所在城市选择当地餐厅
> 3. 视频通话时"云干杯"
> 4. 虽然吃的不同，但决策过程本身就是一种连接
>
> **价值**：突破地理限制，让社交不因距离而中断

---

## 七、总结

喵乐个鱼不仅仅是一个"选餐厅工具"，它是一个**以餐饮为媒介的社交操作系统**。通过将决策过程游戏化、协作化、数据化，它重新定义了"一起吃饭"这件事的意义——重要的不是最终选择了哪家餐厅，而是**大家一起做决定的过程本身**。

在未来，喵乐个鱼将继续深化社交属性，探索更多元的餐饮场景，成为年轻人生活中不可或缺的"聚餐搭子"。
